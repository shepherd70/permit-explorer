# permit-explorer — Audit (2026-08)

**Dimensions run:** security & provenance (secrets across full git history, prompt-injection scan, commit provenance, GitHub repository hardening, live-deployment exposure); correctness of the recent audit-fix delta (PR #20); JavaScript conventions and client-side injection surface; maintainability and dependency/supply-chain hygiene; documentation and licensing quality; SEO/deployment consistency. Regulatory defensibility, statistical-estimator validity, financial-data correctness, and citation/methods integrity are not applicable to this public open-data viewer.

**Baseline:** audit branch `audit/permit-explorer-2026-08` created from `main` at `ec28086`. Full history scanned (47 commits). The working tree was clean. This pass follows PR #20 (2026-07 audit fixes) and Dependabot PRs #21–23 (action major-version bumps), all merged and live.

## Summary

The repository is in good health and **no secret, credential, or API key is exposed anywhere in the working tree or across all 47 commits of history** — the only token reference (`SOCRATA_APP_TOKEN` in `src/m0_validate.py`) is correctly read from the environment and never committed. The PR #20 audit fixes were independently re-reviewed and stand up: SoQL null-semantics are consistent, the compare-failure state machine is sound, SRI hashes match the live CDN files, and the harness (115/115) is genuinely adversarial. There are **no critical findings**. The one issue that deserves priority is a **reflected cross-site-scripting vulnerability** in the "Compare communities" panel: a crafted `?cmp=` share link injects an event handler into an inline `onclick` attribute, because the HTML escaper does not escape double quotes. It is pre-existing (from PR #15), bounded in impact by the site having no authentication, cookies, or stored secrets, but it is real script execution in the app origin and is the top item to fix. Beyond that: a **stale GitHub Pages deployment is still publicly serving the pre-fix June build** (showing the very $0-imputed averages PR #20 corrected, with no canonical tag), the **LICENSE is not machine-detectable**, and several **GitHub repository-hardening switches are off** (secret scanning, push protection, Dependabot security updates, branch protection).

## Major

- **Reflected XSS via the `?cmp=` URL parameter.** `readURL()` accepts arbitrary community names from the URL into `cmpSel` with no validation against the known community list (`src/city_explorer.html:729`), and `renderCmpChips()` interpolates each name into a **double-quote-delimited `onclick` attribute** while `esc()` (`:517`) escapes only `& < >` — not `"` (`:1114`). A share link such as `?cmp=x" onpointerover="alert(document.domain)` renders `onclick="D.cmpRemove('x" onpointerover="alert(document.domain)')">`, injecting an event handler onto the chip's remove button that fires on hover. The `aria-label` on the same element *does* escape `"`; the `onclick` does not. Impact is bounded — the site has no login, no cookies of value, and stores only a theme preference — so there is no session to steal, but it is arbitrary script execution in the deployed origin (usable for defacement or a convincing phishing overlay on a `krevian.com`-branded page) and the CSP still permits `'unsafe-inline'`, so the injected handler runs. Pre-existing since PR #15; PR #20 routed these same names through a new code path one line above the vulnerable sink without noticing it. **Fix (either, ideally both):** in `readURL`, keep only `cmp` names that exist in `this.communities`; and eliminate the quote-fragile inline handler — render the chip button as `onclick="D.cmpRemoveIdx(${i})"` (index-based, no interpolated string) or, at minimum, add `.replace(/"/g,'&quot;')` to the `onclick` interpolation as the `aria-label` already does. The same quote-unsafe idiom exists at the choropleth drill link (`:1050`), lower risk because those names come from Calgary's GeoJSON rather than the URL, but worth the same treatment.

- **A stale GitHub Pages deployment is still live and serving the pre-fix build.** GitHub Pages remains enabled (workflow source) and publicly serves `https://shepherd70.github.io/permit-explorer/` with `last-modified: 2026-06-21` — a build that predates PR #20, so it presents the **$0-imputed average project cost** (the 7.7%-understated figure this project just fixed), the zero-valued compare-failure rows, the mobile overflow, no SRI, and no canonical link. It also has no `rel=canonical`, so it competes with the Cloudflare deployment for indexing. This is both a correctness-exposure (a known-wrong version of the tool is reachable and indexable) and an SEO/duplicate-content problem. Note the deploy workflow `pages.yml` was removed back in commit `30a3ca8`, so this deployment is frozen and will never update — it is orphaned, not merely lagging. **Fix:** disable GitHub Pages in repository Settings (the canonical host is Cloudflare Pages at `yyc-permits.krevian.com`); optionally confirm nothing links to the `github.io` URL first.

## Minor

- **LICENSE is not machine-detectable.** `LICENSE` is the MIT text followed by an appended Calgary data-attribution paragraph after a `---` separator; GitHub's license classifier therefore reports `NOASSERTION` (the API returns no SPDX id and the repo shows no license badge). The intent is fine and the attribution is worth keeping. **Fix:** keep `LICENSE` as the verbatim MIT text only, and move the data-attribution paragraph into `README.md` (it is already substantially covered in the Data & attribution section) or a `NOTICE` file.

- **GitHub repository-hardening switches are off.** Secret scanning, push protection, secret-scanning validity checks, Dependabot security updates, and vulnerability alerts are all disabled, and `main` has no branch protection (`gh api` confirmed). Dependabot version updates work (PRs #21–23 merged), but security-advisory alerts specifically are off, and nothing prevents a direct force-push to `main` or a secret being pushed. For a public repo these are free. **Fix:** enable secret scanning + push protection and Dependabot alerts/security updates in Settings → Code security; add a light branch-protection rule on `main` (require the CI check to pass, disallow force-push).

- **Repository description has a typo and metadata is sparse.** The GitHub description reads "City of Calgary**building** permit data" (missing space); there is no homepage URL set and no topics. **Fix:** correct the description, set the homepage to `https://yyc-permits.krevian.com/`, and add a few topics (e.g. `calgary`, `open-data`, `leaflet`, `chartjs`) for discoverability.

- **`sitemap.xml` `lastmod` is stale.** It reads `2026-07-12`, but the site content changed materially in PR #20 (2026-08-23). **Fix:** bump `lastmod` (and rebuild `dist/`) when content changes; consider deriving it in `build.py` so it cannot drift.

- **A ~950 KB unused data file is committed.** `data/raw/Building_Permits_20260612.csv` (972 KB) is a point-in-time export no longer read by anything — `build.py` is now a stdlib byte-copy and the app queries the live API. It is public Calgary open data (not sensitive), but it is dead weight in every clone and was already flagged as "now unused — left in place" in `TASKS.md` #24. **Fix:** remove it (history retains it) or, if kept as a sample, move it under a clearly-labelled `sample/` path and note why in the README.

- **`cmpRetry()` clears the global error banner.** `cmpRetry` calls `this.clearError()` (`src/city_explorer.html:1111`), which dismisses the shared error banner regardless of what raised it — so retrying a failed community comparison silently hides an unrelated main-query error while the main view is still broken. Compare failures never raise the global banner (the harness asserts this), so the call is unnecessary. **Fix:** drop `clearError()` from `cmpRetry`.

- **Choropleth `cost` min-sample gate counts the wrong denominator.** The `cost` metric's `minN:3` gate tests `c.n` (all permits) while `avgc` now averages only cost-bearing permits (`src/city_explorer.html:572`, `:576`). A community with 5 permits but a single costed one passes the "≥3 data points" gate and is shaded by one value. Low impact (the ramp's 2–98 percentile clamp softens outliers) and the `get` accessor null-guards, so it is small-sample noise, not a crash. **Fix:** add `count(estprojectcost) as costn` to the community query and gate `cost` on that count.

- **`csvCell` numeric exemption misses exponent-form numbers (theoretical).** `/^-?\d+(\.\d+)?$/` (`src/city_explorer.html:1329`) does not match a stringified number in exponent form (|v| ≥ 1e21, e.g. `-1e+21`), which would be apostrophe-prefixed and mangled. Unreachable with Calgary permit data (costs ≤ ~1e9; days-to-issue is now null, not negative), so no fix is required; if desired, `if(typeof v==='number') return String(v);` before the string checks closes it. Other probed bypasses (leading-space `=`, Unicode homoglyph `−`/`＝`, leading tab) are treated as inert text by Excel/Sheets on import. The city-mode server-rendered CSV remains un-neutralizable client-side — an accepted residual already recorded in `TASKS.md`.

- **`#cmp-notice` mixes an interactive control into a live region (a11y).** The Retry link sits inside a `role="status"` region (`src/city_explorer.html:439`, `:1168`); links inside live regions are awkward for screen-reader users to reach and each `innerHTML` rewrite re-announces the whole string. **Fix:** keep the status text in the live region and place the Retry control as a sibling button outside it.

- **`smoke.js` finiteness guard on `d` is weaker than it reads.** `Number.isFinite(+x.d)` cannot fail on `d:null` (`+null === 0`), so it only catches an alias typo, not a genuinely absent average (`test/smoke.js:117`). **Fix:** `x.d != null && Number.isFinite(+x.d)` to assert the aggregate actually produced a value.
